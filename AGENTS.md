# Sidecar Classroom

This repository is a separate HBS workshop app, not the Bachelor's Essay package. Read README.md first. Keep the workshop notes and all BE materials unchanged.

- Publish only tracked app files; never copy parent-folder records, `.private/`, credentials, or live classroom data into the repository or Pages artifact.
- Frontend changes go in `public/`. Database changes belong in CLI-generated migration files. Server changes go in `supabase/functions/classroom/` and require a separate Edge Function deployment.
- Email accounts use Supabase Auth for passwords and hashed, expiring Sidecar sessions. Verify ownership on every activity and nested slide/block/group action; keep email accounts isolated from one another and the sample workspace. Never grant admin access based on an email address or user-editable metadata. No email confirmation is intentional for this version.
- Students can write in draft and live activities, including after timer expiry. Only explicit Pause or End locks student writes. Keep browser/server checks consistent and preserve in-flight drafts across pause/resume. The timer bounds automatic AI work, independently of writing access.
- Show the complete student instructions expanded on entry, preserving line breaks. Students may collapse them without affecting edits; polling updates the text without resetting that choice. Private debrief guidance must never appear there.
- Presentation content must keep large fixed font sizes and paginate longer content; never shrink it to fit. Source links must resolve to authorized current slides and return to the unchanged private-debrief snapshot without exposing instructor notes.
- Preserve instructor/group authorization, RLS and revoked browser privileges, optimistic concurrency, and the private debrief response boundary.
- Do not expose the AI key or instructor key in client config, HTML, links, tests, or logs. Group links may contain only their own capability in the URL fragment. Explicit external testing may use a separate expiring tester capability in the URL fragment, restricted on the server to one dedicated test activity; never use the master instructor key in a link.
- Test-instructor workspace access may create and manage only `is_test` activities. Resolve every nested slide/block/group write to its owning activity; never rely on UI visibility for isolation. Keep the eight-character invitation code out of public files and exchange it for an expiring random capability. Master UI may create, replace, or revoke this invitation.
- Keep workspace AI defaults master-only and API keys write-only. Master, email-account, and test-workspace instructors may choose an available model for a new activity; persist the exact model with that activity and use it for manual/scheduled debriefs without changing the workspace default. Omit model settings from student responses. Validate before saving, preserve working settings on failure, and never place keys in browser storage. Class-code joins must preserve group scope and atomic individual allocation; display names are not authentication.
- Activity templates require master, email-account, or test-workspace instructor access and an editable preview. Copy only slide titles and prompt labels into new decks; response content and contributor names must start empty so template text never counts as student evidence. Keep generated private debrief guidance out of student instructions and session responses.
- Instructor voice input must keep microphone activation explicit, release tracks on stop/close, preserve typed text, and offer typing after permission or network failures. Keep audio out of persistent storage and logs, enforce the server byte cap and independent attempt quota, and keep transcription instructor-only (master, email account, or test workspace). Dashboard deletion must name the activity and require a confirmation; never delete existing user activities for QA.
- AI calls require instructor or scheduler authorization. Keep the empty/unchanged-input skip, concurrency lock, timeout, and bounded input.
- Check `npm test` and `npm run build` after substantive changes. Use disposable live-test records when backend behavior changes. Record actual verification and limits in README.md.
- Keep the Free-plan constraint and other existing Supabase projects/repositories untouched. Never change plans or pause other projects to make room.
