# Sidecar Classroom

Live group slides with a private AI debrief for the instructor.

**App:** https://kamg89.github.io/sidecar/

**Repository:** https://github.com/kamg89/sidecar

This is a small classroom tool inspired by the group-work/debrief workflow in the instructor's October 10, 2026 workshop notes. Groups write directly in their own slide decks. An instructor sees the work on the left and a separate debrief on the right. The notes themselves, private classroom content, and credentials are not part of this repository. This is an independent tool, not a Harvard or Google product.

## Run an activity

1. Open the app and choose **Create account**. Enter your email and a password of at least eight characters; no confirmation email or code is required. Your own activity workspace opens immediately. Return with **Sign in**. **Keep me signed in on this computer** is optional; sessions last seven days and **Sign out** revokes the current session. Existing owner/sample access remains under **Have an instructor access code?** The deployment owner’s private key is different from an OpenAI key and is never committed here.
2. The deployment owner can open **AI settings** to choose the shared default model or replace the API key; leave the key field blank to keep the saved key. **Test connection & save** checks a real structured response before changing anything. Choose **New activity** and **Describe the project**: include the topic, learning goal, task, audience, and any time or slide requirements. You can type or tap the small **microphone** beside the description, allow microphone access, speak, then tap the stop icon. Your transcript is appended as editable text; review it before generating. Recording stops after 90 seconds, and closing the form stops the microphone. A failed upload offers **Retry transcription** while the form remains open. The title is optional. Select **Groups** (1–20 shared decks) or **Individual** (1–60 separate decks), and the number of workspaces. Choose **AI model for this activity** from the connected account’s available models, including version-labeled Luna, Terra, Sol, and other text models. The choice is used for the template and saved with the activity for manual and automatic debriefs. **Debrief preferences** contains the private synthesis focus, slide count (1–6), and optional custom instructions. Click **Generate template**. AI proposes an activity title, student brief, one to four student slides with two to four response prompts each, and private debrief guidance. Review and edit the preview, use **Edit description** or **Regenerate** if needed, then click **Create activity**. Every workspace receives a separate copy with blank response boxes. Generation alone creates no activity; creation opens a draft. Student template slides and private debrief slides have separate counts.
3. Open **Invite class → Present QR code** to project the join screen. Students scan it with their phone camera and go directly to group selection or their display name; no code typing is needed. **Full screen** expands the projection and Escape returns to the instructor view. You can also copy the prefilled invitation or share the student URL plus the six-character class code. Students entering manually open https://kamg89.github.io/sidecar/#join and enter that code. For group work, they select their assigned group; for individual work, they enter a display name and receive a separate deck. No student account or email address is required. Students should keep **Copy my return link** for re-entry; the same browser can also reclaim an individual deck through the original class code. Direct deck links remain available under **Direct deck links & access recovery**. The student workspace displays the task, a full-brief button, and an explicit waiting/open/paused state. Editing is allowed only while the activity is live.
4. Click **Start activity** and set the duration (eight minutes by default, up to 120). Students can use **Go to my response** to reach their writing, add text boxes directly, and open **Slide tools** for formatting, themes, and adding, duplicating, or deleting slides. Text saves after a short pause and visible classroom tabs poll for updates every three seconds. Hidden tabs pause polling and refresh when visible again; server-scheduled AI updates continue. A connection failure shows **Reconnecting…** and keeps unsaved writing in the open tab until it can retry. Updates to other text boxes continue appearing while a student types in their own box. Optional **Contributors** labels attach names to each text box; names are self-reported and remain optional. Choose one recorder per text box; simultaneous changes to the same box produce a visible **Compare edits** prompt instead of silently overwriting saved work. This also applies when a student leaves an older version focused while a teammate saves. The instructor sidebar counts workspaces and text boxes with saved writing; these counts indicate submitted text, not attendance or understanding.
5. Use **Customize** in the debrief panel to choose your purpose and instructions. Automatic synthesis runs on the server every minute while the activity is live, automatic updates are enabled, and time remains. Empty or unchanged work skips the AI call. **Update now** requests a manual update; concurrent/rapid duplicate requests are suppressed.
6. Use the monitor button to open a private second window. Put that on the instructor monitor. **Present debrief** opens a minimal 16:9 slide with synthesis, attributed examples, and a discussion question; private facilitation notes stay out of the projected slide. Use arrow keys, Space, or the controls to navigate, Full screen to expand, and Escape to close. The presented deck stays fixed while new AI drafts arrive; **Load latest** lets you choose when to switch. The separate **Present** toolbar button shows group slides. Sharing a student's group link never shares the debrief. Review AI observations and source links before using them in discussion.
7. Pause or end the activity to stop group editing and automatic AI calls. A paused activity can be restarted with a duration of your choice. If a student is typing when you pause, the unsaved draft stays in that open tab and saves when writing reopens; students should keep that tab open until **All changes saved** appears. Unsaved drafts do not survive closing or reloading the tab. **History** retains prior debriefs; **Export** downloads a JSON backup of the activity and private debrief, without group access tokens. To remove an old activity, use its **trash icon** on the dashboard and confirm the named activity. Deletion is permanent and removes its slides and debrief history; its class code and deck links stop working. **Keep activity** cancels.

Tell students that their slide text is sent to OpenAI to prepare a private classroom debrief. Use only contributor names people agree to display; avoid sensitive information. Omitting names leaves group and slide attribution intact. There is no automatic grading.

## Architecture and access boundaries

The frontend is static HTML/CSS/JavaScript hosted on GitHub Pages. It calls one Supabase Edge Function, `classroom`, over HTTPS. That function validates the owner instructor capability, a registered instructor’s expiring session, an activity-scoped tester capability, a test-workspace capability, or a 256-bit group capability before accessing the database. Students cannot request instructor settings, debriefs, history, other groups' slides, or AI calls. Server responses use an explicit student-safe session projection.

All seven application tables have RLS enabled, with no browser policies and no `anon`/`authenticated` table privileges. Only the server service role accesses them. The service key supplied by Supabase stays inside the Edge Function. `verify_jwt = false` is intentional: protected actions are authenticated by the function’s custom capability/session mechanism. Only account entry and class-code lookup/join are public, with validation and attempt limits.

Supabase Vault stores `OPENAI_API_KEY`, `OPENAI_MODEL`, `INSTRUCTOR_KEY_SHA256`, `SCHEDULER_SECRET`, and `CLASSROOM_FUNCTION_URL`. A zero-argument SQL function exposes the four core runtime values and three test-workspace access values only to the service role. The test-workspace code hash, random session capability, and expiry are encrypted in Vault; the readable code is shown once to the owner when created. Its execute privilege is explicitly revoked from PUBLIC, anon, and authenticated; its search path is empty. The instructor access key is stored only as a SHA-256 hash on the server. Group links are retained in the protected groups table so the instructor can copy them again. No secrets belong in `public/config.js` or GitHub Actions.

The `pg_cron` job calls the Edge Function through `pg_net` every minute, using its own Vault secret. It makes no HTTP call when no eligible activity is live. The AI uses the OpenAI Responses API with structured JSON output and `store: false`. The initial workspace default is `gpt-4.1-mini`; the owner can change it through **AI settings**. New activities save their selected model in `class_sessions.ai_model`, so changing the workspace default does not change those activity choices. Legacy activities with a null model retain their existing workspace-default behavior. The selected model appears beside the private debrief, and is omitted from student responses. The chooser loads text-model candidates from the connected OpenAI account, and saving verifies structured-output compatibility. Larger/slower models can exceed the generation timeout; errors retain the previous debrief. Student text is treated as evidence, not instructions; generated content is rendered as escaped text. Requests give the AI short temporary source references and, for ordinary-sized classes, a schema allowlist of populated text boxes and supporting slides. Returned references are restored to database IDs and checked against actual slides and blocks; empty boxes cannot serve as examples. Large inputs preserve all sources while avoiding the schema enum limit. Names and groups come from saved source records, never model-invented attribution. Quotations are checked against the original text; if the model rewrites a quotation, the server substitutes a bounded literal excerpt from the linked block. Summaries are explicitly labeled as paraphrases. The prompt distinguishes self-reported learning from measured outcomes, keeps single-workspace claims attributed, considers responses across prompts, and checks for unfinished or mixed-language wording. These instructions reduce overclaiming but are not a guarantee; claims still require instructor judgment.

Template generation also runs through the authenticated Edge Function using the activity’s selected model and the saved API key, with OpenAI [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), `store: false`, a 55-second upstream timeout, and validation of both AI output and instructor edits. Master, registered-account, and test-workspace instructors can call it; students and single-activity tester links cannot. The template request includes the project description, optional title, working mode, and debrief focus, but no existing classroom data or custom private debrief text. Custom private guidance replaces the AI suggestion locally at review and is stored only in the instructor session fields on creation. Slide headings become labels, never response content; student names and answers cannot be seeded through this endpoint. Existing blank-work checks therefore continue to skip debrief generation.

The activity dropdown uses the account’s `/v1/models` list, restricted to the existing supported text-model families and excluding Pro variants from this short-request workflow. Labels retain the actual model family and version rather than assigning aliases to other models. The selected model is validated on the server; there is no silent substitution. A failed catalogue request offers an explicit workspace-default fallback or retry. GPT-5/6 requests use low reasoning effort and a bounded extra 4,000 output tokens for reasoning; the 55-second timeout still applies. Current official [Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna) and [Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra) documentation confirms structured-output support and low reasoning effort. Account availability is not a latency guarantee for every listed model.

An authenticated workspace has a separate fixed hourly bucket allowing 12 template-generation attempts, including failures. This reuses the existing server-only atomic attempt counter with a distinct hashed prefix; it does not consume sign-in or student-join quotas. An AI failure preserves the setup form, and no classroom records are written until the instructor accepts the preview. Requests from older open tabs can still use the legacy three-prompt creation payload during deployment. No new table or configuration secret is needed.

Each activity is bounded to 20 groups or 60 individual places, eight slides per workspace, and six text boxes per slide. An AI request refuses oversized input instead of silently dropping groups. The scheduler processes at most four eligible activities per invocation. Several simultaneous instructor classes share that capacity and the same free-plan quotas; large multi-class deployment has not been load-tested.

## Instructor voice input and hosting limits

Voice input uses the browser’s `getUserMedia` and `MediaRecorder` APIs, then sends the completed recording to the existing authenticated `classroom` function. The function forwards it as multipart data to OpenAI’s [`/v1/audio/transcriptions`](https://developers.openai.com/api/docs/guides/speech-to-text), using [`gpt-4o-mini-transcribe`](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe) and the existing server-held key. This fixed transcription model is separate from the activity’s template/debrief model. Native recording avoids a new SDK, streaming service, or hosting provider. The browser chooses WebM/Opus or MP4 according to supported recording formats. Unsupported browsers or denied permission retain normal typing.

Master, registered-account, and test-workspace instructors can submit recordings. Audio is capped at 90 seconds in the browser and 2 MiB on the server, including streamed requests without a Content-Length header. A separate atomic bucket allows 12 transcription attempts per workspace per hour. The upload uses a 55-second upstream timeout. Audio stays in temporary memory and is forwarded to OpenAI; Sidecar does not write it to Postgres, Storage, GitHub, or application logs. Failed recordings may be retried while the form stays open; closing it discards the local copy and cancels a pending upload. Cancellation cannot undo a request already received by OpenAI. The transcript remains editable and does not create an activity until the instructor accepts the generated template. Transcription may make mistakes, including on silence; review the wording.

October 10 footprint check: the static site is approximately **193 KB**, compared with GitHub Pages’ **1 GB** published-site limit. Sidecar’s database is approximately **12.4 MB**, compared with the Supabase Free limit of **500 MB per project**, with zero stored audio objects. Kamfree still reports `free`; this revision adds no project, table, storage bucket, Edge Function, scheduler, dependency, or paid hosting add-on. It adds one authenticated function call per submitted recording and reuses the existing deletion endpoint. [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) and [Supabase quotas](https://supabase.com/docs/guides/platform/billing-on-supabase#variable-usage-fees-and-quotas) were checked against current documentation.

Monthly traffic remains a capacity constraint: GitHub Pages has a 100 GB soft monthly bandwidth limit; Supabase Free includes 500,000 function invocations and 5 GB uncached egress shared across the organization. The existing three-second classroom polling is a larger recurring cost than these optional controls: 65 students plus one instructor make roughly 13,200 polling requests during ten minutes, before joins, writes, and other calls. This is an estimate, not a billing measurement or a fresh load test. The connected tools expose project size, plan, and recent logs, but did not expose organization-wide monthly usage; no signed-in dashboard browser was available to verify remaining monthly headroom. Check [Kamfree usage](https://supabase.com/dashboard/org/oqjuoinnsdftjkogpflk/usage) for ongoing use across projects. OpenAI transcription and generation remain separately billed API usage; free hosting does not cover inference. Hidden classroom tabs now pause polling and refresh on return. End activities and close unused tabs after class.

## Class access and individual work

A class code authorizes entry to that activity, not to instructor controls. Anyone with a group-mode class code can choose a group, so share it with the intended class. Students see only the selected group's deck. In individual mode, the server allocates an unclaimed deck atomically; students cannot browse classmates' names or select somebody else's deck. A random browser-held return capability reopens the same individual place without using a display name as a password. Returning on a new device requires the private deck link or instructor help. Display names are self-reported, not authenticated identity.

**Invite class → Close joining** prevents new code-based entry. **Replace code** invalidates the current code, its QR link, and any preserved older code. New codes use six characters, displayed as `ABC-234`, without O, I, L, 0, or 1; lowercase, spaces, and dashes are accepted. Previously shared 12-character codes remain valid after the initial upgrade until the instructor replaces the code. Individual return capabilities are stored against the activity ID so a later code change does not consume another place in the same browser. Existing private deck links continue working; pause/end the activity to stop edits, or replace a particular deck link for access recovery. Class codes and individual claim hashes never appear in student session responses, and exports omit the class code and deck access tokens. Code-entry requests have a server-side rate limit with short-lived hashed network buckets.

The API key and workspace-default model controls require the master instructor capability. Activity setup exposes a separate model catalogue to master and test-workspace instructors; it returns model IDs and the default, never the key. Students and single-activity tester links cannot call this catalogue or generate templates. Students and scoped outside testers cannot read or change those settings. The fixed-purpose Vault setter accepts only the OpenAI key/model fields and is executable only by the Edge Function's service role. It cannot modify other Vault secrets or projects. The key remains write-only from the UI; the password field starts blank, and a successful save clears it.

## Development and deployment

Node 22 or newer is required. QR images are generated locally using the vendored [qrcode-generator 2.0.4](https://github.com/kazuhikoarase/qrcode-generator) encoder; no external QR service receives the class link. Its source and MIT license are in `public/vendor/`. The package is pinned for byte-for-byte verification, and jsQR 1.4.0 independently decodes generated QR images in tests. Linkedom is a pinned development-only DOM test dependency. The lockfile is committed.

```sh
npm ci
npm test
npm run dev
# Local preview: http://127.0.0.1:4173
npm run build
```

Pushes to `main` run tests, build `dist/`, and publish through the Pages workflow. The production endpoint is in `public/config.js`; it is public connection metadata, not a secret. Relative asset paths support the `/sidecar/` project URL.

The Supabase project is **Sidecar Classroom**, reference `hebqieisdhbnxukoktjs`, in the owner-selected **Kamfree** organization, US East. Supabase quoted **$0/month** at creation on October 10, 2026. OpenAI API usage is billed separately to the configured key; GitHub/Supabase free hosting does not make AI inference free.

The database migration is in `supabase/migrations/`. The Edge Function source is in `supabase/functions/classroom/`. For deployment from an authenticated Supabase CLI:

```sh
supabase functions deploy classroom --project-ref YOUR_NEW_PROJECT_REF --no-verify-jwt --use-api
```

Apply the migration only to the intended new project. Install Vault values privately; never put their values in source, migrations, logs, issue comments, or build artifacts. Configure the function URL and the allowed frontend origins for any new deployment. On this deployment, Vault was configured through the connected Supabase management tool because the local CLI did not have a management access token. GitHub Pages redeploys do not redeploy the Edge Function or alter the database.

To replace an OpenAI key, sign in with the master instructor key and open **AI settings**. Paste the replacement key, refresh the available models if needed, select a model, and click **Test connection & save**. The key is sent over HTTPS to the authenticated server, validated with OpenAI, and saved in Supabase Vault; it is never returned to the browser or stored in browser storage. A failed check leaves both saved values unchanged. New debriefs reload the saved API key and use the activity’s selected model, or the workspace default for older activities without a saved choice. Revoke the old key in OpenAI after the replacement is working. The setup key supplied in chat should be rotated before classroom use.
